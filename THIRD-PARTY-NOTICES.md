go-ha2fabric is licensed under the Apache License 2.0 (see
[`LICENSE`](LICENSE)). It depends on six Go modules directly; every
further dependency is a decision recorded here (MIT, Apache-2.0, BSD and
the equivalent ISC only, checked by `make licenses`). No third-party
source is copied into this tree.

The licence and notice texts of everything linked into the daemon are in
[`licenses/`](licenses/), generated by `script/licenses/generate.sh` and
checked in CI (`--check`): `licenses/MODULES.txt` lists the linked modules
at their versions, `licenses/modules/<module>/` holds each module's texts
(go-fabric's `NOTICE` with matter.js's `NOTICE` it points to, go-fabric-ui's
npm licences of the embedded web bundle), `licenses/go/` the Go standard
library's. The release archives carry the tree beside this file; both
images carry it in `/usr/share/doc/go-ha2fabric/`. The same check fails
when a direct requirement below is not named at `go.mod`'s version.

The recorded fixtures under
`testdata/ha/` are shapes of Home Assistant's WebSocket messages written
for the tests (each names the Home Assistant core lines it mirrors), not
copies of its source.

## Direct dependencies

### go-fabric — Apache-2.0

The Matter side: the `node` facade, the device kit (`device`), `contract`,
`eligibility` and the generated `<cluster>def` packages; in tests its
in-process controller (`fabrictest`).

- Source: <https://github.com/thingfabric/go-fabric>, module `thingfabric.dev/go-fabric`, pinned `v0.28.0`.
- Copyright (C) 2026 SukramJ. Apache License 2.0. Its `NOTICE` (go-fabric
  is a semantic port of matter.js, Copyright matter.js contributors,
  Apache License 2.0) and matter.js's `NOTICE`, with its own
  `THIRD-PARTY-NOTICES.md`, are in
  [`licenses/modules/thingfabric.dev/go-fabric/`](licenses/modules/thingfabric.dev/go-fabric/).
- Decision: concept v8 decision 0.2 — the daemon embeds go-fabric in
  process.

### go-hamapping — Apache-2.0

The table: which Home Assistant entity becomes which device type and
cluster, and which controller command becomes which entity command.

- Source: <https://github.com/SukramJ/go-hamapping>, module `sukramj.dev/go-hamapping`, pinned `v0.10.0`.
- Copyright (C) 2026 SukramJ. Apache License 2.0.
- Decision: CONCEPT.md, Shape — the mapping is go-hamapping's.

### go-fabric-ui — Apache-2.0

The web interface: the `fabricui` handlers and the built bundle embedded in
the module (Svelte 5 pages compiled at go-fabric-ui's release; no Node.js
in this build).

- Source: <https://github.com/thingfabric/go-fabric-ui>, module `thingfabric.dev/go-fabric-ui`, pinned `v0.16.0`.
- Copyright (C) 2026 SukramJ. Apache License 2.0; the bundle's npm
  licences and its `THIRD-PARTY-NOTICES.md` are in
  [`licenses/modules/thingfabric.dev/go-fabric-ui/`](licenses/modules/thingfabric.dev/go-fabric-ui/).
- Decision: go-fabric concept v9 — one UI for the family's daemons
  (brief H3 §2.8).

### go-hamqtt — MIT

The vocabulary go-hamapping reads: `model.Device`, `model.Entity`,
`model.State`, `model.Command`.

- Source: <https://github.com/SukramJ/go-hamqtt>, module `sukramj.dev/go-hamqtt`, pinned `v0.41.0`.
- Copyright (c) 2026 SukramJ. MIT License.

### go-ha-catalog — MIT

Home Assistant's tables; the daemon reads the MQTT schema's payload

- Source: <https://github.com/SukramJ/go-ha-catalog>, module `sukramj.dev/go-ha-catalog`, pinned `v0.4.0`.

The WebSocket transport of the Home Assistant client: pure Go,
context-aware, concurrent writes; the server family's choice.

- Source: <https://github.com/coder/websocket>, module `github.com/coder/websocket`, pinned `v1.8.15`.
