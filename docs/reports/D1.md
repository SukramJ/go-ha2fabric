## Differences from the brief

- go-fabric-ui v0.8.0 was tagged before the wave started; bumped in its own
  commit.
- mDNS findings: warnings carry none today, so the start-up log
  (`ha2fabric.mdns_interface`), and only the `interface_*` codes and only
  with the list set — the other codes (`non_default_commissioning_port` on
  every registry node, say) would be start-up noise; the web UI's mDNS page
  already shows the whole diagnosis.

## Decisions

- `discards` survives an erase (`served.discarded`): the contract's value
  is "since the host started". A deleted registry node's count leaves the
  sum.
- `MDNS_INTERFACES` refuses an empty item anywhere (`eth0,,br30`,
  `eth0, `); a blank value is every interface.

## Left out

- A test that drives a discard through the daemon and reads the counter
  (needs a controller; the bridge-level count is held by
  `bridge_c2_e2e_test.go`).

## Questions

- A rename while a registry node has no run (failed start) changes only the
  record; if its store holds a label persisted by an earlier live rename,
  go-fabric restores that over the configured one at the next start.
  Acceptable, or set the label before `Start` (which would also override a
  controller-written label)?
