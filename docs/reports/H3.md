## 2.2 Exposure with labels — `e861e45`

`expose.Rule{IncludeLabels, ExcludeLabels, Overrides}`, `expose.Entity.Labels`
(entity ∪ device, label ids), `expose.Labels` (label_id → name) with
`Resolve` (name case-insensitively, else the id; an unresolved value is the
id as given — D1) and `Rule.Unresolved`. `Decide(e, labels)`: disabled,
hidden, override, exclude (ids, globs, labels), include (ids, globs,
labels), Assist; `Decision.Source` is one of `disabled`, `hidden`,
`override:on`, `override:off`, `rule:exclude`, `rule:include`, `rule:label`,
`rule:assist`; the reason names the label by its registry name ("included
by label 'Matter'"). An unresolved value is a warning in the log
(`bridge.label_unresolved`, once per change) and in `Bridge.Status().Warnings`;
with the 0.1.0 JSON routes removed (Q5) no HTTP route carries them, and
go-fabric-ui's status has no field for host warnings.

## Differences (from the brief)

- **2.3 was no bug** (above); the test is added anyway.
- **`Apply` does not resync itself.** go-fabric-ui's handler calls
  `Options.Reassemble` after every successful `Apply`
  (`fabricui/handlers_exposure.go` `exposureApply` at `v0.1.0`), and
  Reassemble is the full resync; a second one inside `Apply` would run the
  sync twice per change.
- **Events twice.** After a UI apply the handler publishes
  `exposure_changed`/`endpoints_changed` and the bridge's `OnChange` does
  too for the same sync; a change from Home Assistant reaches the stream
  only through `OnChange`. The page refetches either way.
- **The labels filter** is the column's distinct values, i.e. label
  combinations ("Kitchen, Matter"), because the UI matches a filter by
  equality (`ui/src/lib/pages/node/Selection.svelte` `filtered`); the search
  matches single labels. See Q2.
- **A removed and re-added endpoint gets a new number** (go-fabric's
  Aggregator); `TestWebUI` asserts only that it returns.
- **A name override** is the entity's name; go-hamapping composes it with
  the device name (`plan.go` `options`, `device.ComposeNodeLabel`) unless
  it already starts with it, so the node label is not the override alone.

## Decisions

- Owner, 2026-10-25, on the questions: Q1 — reserve the endpoint number
  per stable key, no grace (a go-fabric gap, wave CK; nothing in this PR);
  Q2 — a go-fabric-ui patch; Q3 — open for a later go-hamapping wave; Q5 —
  the 0.1.0 routes removed now.

- Provider inside `internal/bridge` (it reads the bridge's last snapshot
  and dry runs); `internal/selection` a package of its own.
- Stand-alone UI read-only by default; `WEB_ADMIN=true` selects token mode,
  documented as "anyone who reaches the port can write".
- The 0.1.0 JSON endpoints are removed in this release (owner decision on
  Q5, 2026-10-25).
- Label lists split on commas and newlines, not spaces.
- An override that equals the rule's own answer is removed, so the UI can
  hand an entity back to the rule.

## Questions

- **Q1 (owner).** Removal grace and number reservation. matter-hub closes
  an endpoint its filter drops and keeps its number for a re-inclusion
  (`bridge-endpoint-manager.ts:949-965`, #468, #404), and waits 300 s before
  deleting one whose entity left the registry (`:55-59`, `:968-999`). We
  remove at once, and go-fabric numbers a re-added device anew. Wanted: a
  grace, a reservation of the number per stable key, both, or neither?
  The reservation is a go-fabric gap (CJ/CK): the Aggregator would need to
  keep a removed stable key's endpoint number in the store and hand it back
  on `Add` (e.g. `node.Batch.Remove` keeping the number, or
  `node.Config.Bridge.ReuseNumbers`).
- **Q2 (go-fabric-ui).** A filter matches `Item.Fields[field]` by equality,
  so a multi-valued field (an entity's labels) filters by combination.
  Needed: a list-valued field or a "contains" filter option
  (`fabricui.Filter.Multi bool`, matched by membership in a comma list).
- **Q3 (go-hamapping).** A web UI rename is composed with the device name.
  Needed, if the owner wants the override verbatim as the node label: an
  `Options.Name func(model.Entity) (string, bool)` or a
  `Description` flag that skips `ComposeNodeLabel`.
- **Q4 (go-fabric, unchanged from H2 Q2).** The e2e tests still run the
  bridge on `fabrictest.Device.Node()`; a daemon-composed `node.New` cannot
  join a site (CJ). The UI's Observers are therefore not exercised against
  the site's node in the e2e (the stream's events come from the handler and
  the bridge's `OnChange`).
- **Q5 (owner).** The `GET /api/health` and `GET /api/plan` aliases go in
  0.3.0 as the changelog says; drop them earlier? — Decided 2026-10-25:
  removed in this PR.
