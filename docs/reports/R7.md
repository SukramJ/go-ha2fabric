## go-fabric issue candidate: a typed commit error per batch operation

**Why.** Since v0.26.0 `Partition.Batch` holds an `Add`, `Replace` or
`Forget` whose key another endpoint serves at the call, answers it nil and
judges it once `fn` returned (`Partition.Batch` doc `node/aggregator.go:523-548`,
`Batch.Add` `:619-654`, `Batch.Forget` `node/reserve.go:412-462`,
`commitPending` `node/aggregator.go:944-997`). A refusal then reaches the host only inside
`Batch`'s `errors.Join`, as `fmt.Errorf("%w: %s", ErrDuplicateKey, key)` or
`ErrUnknownKey` with the key in its text (`judgeLocked` `:1004-1039`,
`commitForgetLocked` `node/reserve.go:464-483`) — sometimes a part key, not
the call's own. A host that keeps state per call (go-ha2fabric: a group's
signature, a forget to retry) cannot tell which call was refused without
matching text. go-ha2fabric now derives it from `Aggregator().Endpoints()`
after the batch, which works for Add and Replace (instance identity) but
needs the host to re-implement the "another endpoint serves the key" rule
for a Forget, and cannot see the store-side failures of an applied one.

**Shape (proposal).** A typed error per refused or failed held call, joined
as today: `type OpError struct { Op OpKind /* Add, Replace, Remove, Forget */;
Key string /* the call's key */; Seq int /* the call's place in fn's call
order */; Err error }` with `Unwrap() error` (so `errors.Is(err,
ErrDuplicateKey)` still holds), and the same wrapping for the
undo of `refuseLateCollisionsLocked` and for a Forget's erasure error. A host
reads them with `errors.As` over the joined error. Alternative: `Batch`
returns a per-call result (`[]OpResult`) beside the error.

**Acceptance.** Every error `Partition.Batch` returns for a call names that
call (kind, own key, call order) through `errors.As`; the call's sentinel
stays reachable with `errors.Is`; a test per held kind (Add, Replace,
Forget) refused at the commit, and one for a late-collision undo; the
CHANGELOG line; godoc of `Partition.Batch` names the type.

**Stays in go-ha2fabric.** `settle` keeps reading the set until the type is
released; then it switches to `errors.As` and drops `servedKeys`.

**Open.** Whether `Seq` or the `fn` call index is the better handle; whether
a Remove gets the type too (its refusal is at the call today).
