## Differences (from the brief)

- **`Filter.Multi` not set.** The labels filter is the column's own
  (`Column.Filter`), which `Column.Multi` makes a membership filter
  (go-fabric-ui U1a §1); `Filter.Multi` belongs to a fixed filter, and the
  daemon has no fixed labels filter.
- **"Any other half-valid option"** is one more finding: the overrides
  file moved aside (`selection_corrupt`). The configuration itself has no
  other half-valid value — `config.Load` refuses every invalid one.
- **The release run moved to a worktree.** The main checkout was switched
  to `main` by another process at 20:44 while `make release` ran (the
  guards above it had finished on `5346278` at 20:35); release, docker and
  addon-image were run again in a separate worktree of `f1/bump` at the
  same HEAD (a sibling directory: the snap Docker daemon reads neither
  `/tmp` nor hidden directories under `$HOME`). The main checkout was left
  on `main` as found.

## Questions

- **Q1 (owner).** go-fabric v0.13.0 keeps every stored endpoint number
  until `Forget`. The daemon never calls `Forget`, so the number of an
  entity deleted from Home Assistant stays reserved in the store forever
  (before, the first sync's `MarkComplete` freed the numbers of keys absent
  at start). Wanted: `Forget` on an `entity_registry_updated` `remove`
  (the entity is gone for good), or keep every number?
- **Q2.** A label name with a comma would split into two chips under
  `Column.Multi`, which reads the field as a comma list. Accept (rare), or
  ask go-fabric-ui for another separator?
