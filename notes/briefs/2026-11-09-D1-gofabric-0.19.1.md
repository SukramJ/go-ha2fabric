## 4. Counters — `discards` in the status JSON (#51 comment)

go-fabric-ui 0.8.0 has `Options.Counters func(ctx) []fabricui.Counter`
(`Code`, `Value`, `Message`) rendered in `Status.counters` and on the Node
Status page. The list is host-wide, as `Warnings` is (go-fabric-ui 0.8.0:
registry nodes read the same list through the default handler's
`sibling`). Wire it in `cmd/ha2fabric/main.go:112-116` beside `Warnings`
(`:140-148` pattern): one counter `discards`, value the sum of
`Status.Discards` over the configured node's bridge and the registry
nodes' bridges (read how `warnings(def, fl)` reaches the fleet's members),
message "Controller commands answered
with success that called nothing (an Off on a scene's, script's,
automation's or button's plug)". Documents: `docs/operations.md:157` (the
`bridge.command_discarded` row: "counted as `discards` in the status
JSON and on the status page"), "The web UI" (`:270-301`: the status page
lists the counters), "Health" (`:304`: `counters`). Changelog `### Added`.
Also from the comment, into "Scripts, scenes and automations" (`:189-196`):
an ecosystem's tile may drift to its last commanded state because the plug
always reads off, so a tap re-sends Off and lands in the discard path, and
one voice command may arrive as two Offs about a second apart — observed
on an Alexa fabric (go-ha2fabric#51, 2026-11-09); voice "turn on" is the
working control. That is a field observation, cited to the issue, not a
Home Assistant or matter-hub fact.

## 5. Live rename — `Node.SetNodeLabel`

node's NodeLabel at run time, validated (≤ 32 bytes, `CONSTRAINT_ERROR`),
persisted, reported to subscribers. `cmd/ha2fabric/nodes.go:458-478`

registry rename, with the `nodeLabel` truncation (`:345-361`) applied as
at start; an error from the node is logged (`ha2fabric.node_renamed` with
the error attribute) and does not undo the registry rename. Comment and
`docs/operations.md` "Nodes" (`:329-375`) updated: a rename reaches
controllers at once. Test in the nodes test: after Rename, the node's
BasicInformation NodeLabel reads the new label (a `fabrictest` read or the
node's own getter — use what the existing tests use). Changelog `### Changed`.
