## §2 Where Erase lives: `served` becomes the node's owner

Today `served` (`nodes.go:29-41`) is one node's run: `n`, `br`, `prov`,
`events`, `cancel`, `done`. After an erase the node, the bridge and its
worker are new, while the web UI's handler keeps the values it was given
(`Options.Node`, `Exposure`, `Reassemble`, `Events`; `handler.go:369-386`).
So `served` becomes the owner that outlives its node, and the things the
handler holds are the owner's:

- `served` keeps what `serve` was given — `client`, `fan`, `ncfg`
  (`node.Config`), `in`, `sel`, `log` — plus one `events *fabricui.Events`
  (made once, not per node), `prov *exposure.Provider` (made once, over
  `served` as its `Model`), `op sync.Mutex` (serialises `erase` and
  `close`), `closed bool`, `mu sync.RWMutex` and the current run:
  `n *node.Node`, `br *bridge.Bridge`, `cancel`, `done`.
- `serve(base, …)` builds the owner and calls `s.start(base)` — today's
  `:52-83` moved into `start`, with `OnChange` publishing on `s.events`
  and the bridge made over `s.ncfg`; `start` returns the error `serve`
  returns today.
- `served` implements `exposure.Model`: `View()` forwards to the current
  bridge under `mu.RLock` (a zero `bridge.View` without a run).
  `s.Resync(ctx)` forwards likewise; `s.node() *node.Node` reads the
  current node (nil without one); `s.running() bool`.
- `sw *fabricui.NodeSwitch` is the owner's, made once in `serve` as
  `fabricui.NewNodeSwitch(n)` with the first node; `start` ends with
  `s.sw.Set(n)` on success, and a failed come-back leaves no target
  (`s.sw.Set(nil)`, or what 0.7.1 ships for "no target" — Sources). The
  web UI never holds a `*node.Node` of ours. **No `cmd/ha2fabric/source.go`**,
  no follower of our own. `served` also keeps `lost error` and `lostAt
  time.Time` under `mu`: the error of the last failed come-back, cleared
  by a successful `start`; `s.Warnings(ctx)` returns `s.prov.Warnings(ctx)`
  plus, while `lost != nil`, one `fabricui.Warning{Code:
  exposure.WarningNodeEraseFailed, Message: "the node did not come back
  after the erase: <err>; Erase again or restart the daemon", Since: lostAt}`.
- The composition root (`main.go:112-116`): `Node: def.sw`,
  `Exposure: def.prov`, `Reassemble: def.Resync`, `Events: def.events`,
  `Warnings: warnings(def, fl)` — one closure that joins `def.Warnings(ctx)`
  and `fl.Warnings(ctx)` (a registry node's handler reports the default's
  `Warnings`, `handler.go:401`, so every node's status page shows every
  node's finding; a registry node's message starts with `node <key>:`) —,
  `Erase: def.erase`.
- The fleet (`nodes.go:232-237`): `entry` sets `e.Exposure = m.s.prov`,
  `e.Reassemble = m.s.Resync`, `e.Events = m.s.events`,
  `e.Erase = func(ctx) error { return f.Erase(ctx, key) }` whenever
  `m.s != nil`, and `e.Source = m.s.sw` **only while `m.s.running()`**:
  with `Source` nil the node is listed `enabled` false and its routes
  answer as the family's without a node (`options.go:108-109`,
  `handler.go:437`) — the state the fleet already shows for a node that did
  not start (`nodes.go:173-177`). `fleet.Erase(ctx, key)` takes `f.op` (as
  Create, Rename, Delete), refuses after `Close` with `errStopping` and an
  unknown key with an error, and calls `m.s.erase(ctx)`; `fleet.Warnings(ctx)`
  collects each member's `s.Warnings` under `f.mu`.

Why both nodes hand over a switch: one shape (the architecture standard,
"no convenience seam"). The default node's handler is built once on
`Options.Node` (`handler.go:369-386`), so only a switch brings the new node
to it; a registry node's handler would be rebuilt for a new `Source` value
(`registry.go:163-176`, `embedding.md:125-127`), but with the switch the
value is the same and the handler is kept — the configured and the
registry node then behave alike across an erase, and the rebuild path stays
unused rather than being a second mechanism. `Exposure` and `Events` are
the owner's and the same values across an erase either way.

Best architecture under the standard: yes — the owner/run split is the one
that the facade's "a Go node is single-use" (`node.go:39-41`,
`factory_reset.go:30-33`) asks a host for, it keeps `internal/bridge` a
reconciler over one node (no `Rebind`, no lifecycle in the bridge) and
`internal/exposure` almost untouched (its `Model` interface,
`exposure.go:33-36`, already is the seam; one warning code is added beside
the two it has, `:320-327`), and the composition root stays the only place
that knows how a node is made and remade. A `Bridge.Rebind(n)` was weighed
and rejected: the groups it holds are devices of the old node's aggregator,
so a rebind is a full rebuild in disguise. The following `NodeSource` is
go-fabric-ui's `NodeSwitch` (decided 2026-11-08): every host that erases in
place needs it, so it is written once, there.

## §3 The sequence (`served.erase`)

```
op.Lock; closed → errStopping
ectx := context.WithTimeout(context.WithoutCancel(ctx), eraseTimeout)   // 30 s
mu.Lock                                   // readers wait: nobody sees a stopped node
  if n != nil {                           // a run to reset; nil after a failed come-back: the retry only starts
    fan.Remove(br); cancel(); <-done      // the worker drained (Run ends between work items, bridge.go:183-205)
    infos := n.FabricInfos(ectx)          // for the log: how many fabrics leave
    rerr := n.FactoryReset(ectx)          // the fabrics leave with the Leave event, the node stops, store and endpoint records erased, UniqueID re-pinned, DB closed
    n, br = nil, nil
  }
  serr := s.start(base)                   // node.New from ncfg, Start, logFabrics, logPairing, a new bridge on s.events, its worker, fan.Add → Connected → first sync → the endpoints; sw.Set(new node)
  if serr != nil { lost, lostAt = serr, now; sw.Set(nil) }   // the old target is out; node(), running() say "none"
  else            { lost = nil }
mu.Unlock
log ha2fabric.node_erased {fabrics_removed, elapsed} or ha2fabric.node_lost {error}
return errors.Join(rerr, serr)            // 500 on the page; the daemon keeps running
```

Points settled:

- **No `n.Stop` before the reset.** FactoryReset removes the fabrics
  through RemoveFabric only on a started node (`factory_reset.go:49-58`);
  on a stopped one it erases the store without the Leave (`:27`, `:49`),
  and the controllers would keep a live-looking node. The reset stops the
  node itself (`:59-61`). The issue's and the owner's sequence listed
  `n.Stop`; the facade says otherwise — the brief follows the facade.
- **The bridge is detached first**, as `close` does (`:126-128`): no
  sync may touch the node while it resets. An in-flight sync finishes
  under its cancelled ctx (`ReadSnapshot` fails on it; a `Batch`
  already running completes); `<-done` bounds the wait.
- **Detached from the request.** The handler passes `r.Context()`
  (`handlers_node.go:373`); a page that closes the fetch would cancel a
  reset half-way. `erase` runs on `context.WithoutCancel` with its own
  30 s bound, as the shutdown does (`main.go:131`); the request's ctx
  governs nothing but the caller's wait.
- **`mu` is held across the swap.** `View`, `Resync` and `Warnings` (ours)
  wait a few seconds instead of reading a stopped bridge; a `Resync`
  queued during the erase lands on the new bridge. The switch is
  go-fabric-ui's and not behind `mu`: between FactoryReset and `Set` its
  target is the stopped node, so a status poll in those seconds gets what
  a stopped node answers (`ErrStopped`, `node.go:39-41`) — the page polls
  every 2 s until the status answers, as it does for a restart (U7 "Open
  questions" 1). `Set(new)` is called inside `mu`, before `Unlock`, so no
  reader of ours sees the new node before the switch does.
- **The new node** comes from the same `ncfg` (`config.Node`, `node.go:37-58`):
  same listen address, passcode and discriminator, so the pairing codes are
  the same and are logged again (`logPairing`); `logFabrics` logs `count=0`
  with its hint — right after `ha2fabric.node_erased`, which explains it.
  The commissioning window opens as for a fresh store.
- **Selection kept.** `selection.json` (`sel`) is the operator's choice of
  entities, configuration beside the store, not Matter state; FactoryReset
  erases what the node persisted and names a host's own
  `EndpointPersistence` as the host's to erase (`factory_reset.go:36-37`) —
  the selection is neither. Delete removes it because the node ceases to
  exist; an erase keeps the node. The first sync after the erase applies
  it at once (the same `in` closure), so the new node serves the same
  entities under fresh endpoint numbers (the records are erased,
  `:89-91`; the keys are the bridge's and unchanged).
- **Events and the stream.** `s.events` outlives the node, so the new
  bridge's `OnChange` reaches the handler. Open SSE streams observe the
  old node until the page reconnects (U7 "Open questions" 1, accepted);
  a stream opened after the erase observes the new node through the
  switch's `Observe`.
- **Failure handling (decided 2026-11-08: the daemon stays up).** A
  FactoryReset error does not stop the come-back: the node is stopped
  either way (`stopLocked` sets `stopped` first, `node.go:927-931`), and
  the store is erased as far as it got; `start` runs, the joined error is
  returned (500, the page shows it) and logged. A `start` error leaves the
  owner without a run: `node()` nil, `running()` false, `lost` set, the
  switch without a target — **no `os.Exit`, no `lost` channel into `run`'s
  select**; the same rule holds in go-fabric-server (wave S7). The error
  is logged `ha2fabric.node_lost` and surfaced through the existing
  `Warnings` (`fabricui.Options.Warnings`, `options.go:268-286`) as
  `node_erase_failed` (§2), which the status page shows as a chip; the
  status handler includes the warnings before its node check
  (`handlers_node.go:150-158`), so the finding is visible whether or not a
  node answers. What the UI answers for the **configured node** meanwhile:
  the handler's no-node paths are 200 with `enabled` false on
  `GET /node/status` (`handlers_node.go:131-133`, `:157-160`) and 503
  `service_unready` "Node not available" on every other node route
  (`handler.go:519-522`, `problem.go:76-79`) — those paths test
  `h.node == nil`, which a non-nil switch passes, so whether a switch
  without a target lands there is 0.7.1's to define (Sources, unverified);
  the implementer reads it at the tag and the daemon test asserts what the
  contract says. **Retry:** the next `POST /node/maintenance/erase` — it
  reaches `h.erase` while `Options.Node` is the (non-nil) switch
  (`handlers_node.go:354`) and the sequence above skips the reset and only
  starts — or a restart of the daemon, which comes up on the erased store.
  For a **registry node** the fleet keeps the member with its owner; the
  entry's `Source` is nil while it does not run, so it is listed `enabled`
  false and its routes answer as without a node (`options.go:108-109`,
  `handler.go:437`; the state of a node that did not start,
  `nodes.go:173-177`, `operations.md:348-350`); `NodeEntry` has no error
  field (`options.go:97-132`), so its error is the same `node_erase_failed`
  warning with `node <key>:` in the message, on every node's status page
  (`handler.go:401`). Its erase route answers 503 while `Source` is nil
  (`handlers_node.go:354-357`), so its retry is a restart of the daemon,
  or `Delete` (which works without a run, `nodes.go:308-344`) and Create.
- **Concurrency.** `op` serialises `erase` with `close`: a shutdown
  during an erase waits for it, then closes the new node; an erase after
  `close` answers `errStopping`. The fleet's `op` serialises a registry
  erase with Create, Rename, Delete and Close; `List` reads under `f.mu`
  and does not wait. Two erases of the same node queue on `op`; the
  second resets the fresh node (harmless, logged).
- **Unchanged.** `--dump-plan` (`main.go:83-84`, `:190-241`) runs before
  any node exists. The registry's `Delete` (`:308-344`) keeps `leave` +
  `close` + `RemoveFiles`: the issue asks for Erase beside it, not
  instead; a Delete over FactoryReset is a candidate (§9). `leave`
  (`:347-362`) unchanged; `Rename`, `Create` unchanged but for the owner's
  shape.
- **Logs.** `ha2fabric.node_erased` (info; `node=<key>` for a registry
  node, `fabrics_removed`, `elapsed`), `ha2fabric.node_lost` (error; the
  node did not come back after an erase, `node=<key>` for a registry node;
  the daemon keeps running). Rows in `operations.md` (§6).
